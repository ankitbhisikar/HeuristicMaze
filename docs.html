A* Pathfinding Algorithm Fundamentals

A* (A-Star) is an optimal, complete, and mathematically informed graph search algorithm. It dynamically discovers the shortest path from a Start node (S) to a Goal node (G) by balancing actual path cost against an estimated distance heuristic.

Evaluation Function: f(n) = g(n) + h(n)

f(n) = g(n) + h(n)
  • g(n): The exact accumulated cost from the initial Start node to the current node n.
  • h(n): The estimated heuristic cost from node n to the target Goal node.
  • f(n): The total estimated lowest-cost path going through node n.

Mathematical Guarantees

If the heuristic function \(h(n)\) is admissible (it never overestimates the true remaining cost to the goal) and consistent (monotonic, satisfying the triangle inequality), A* is mathematically guaranteed to find the true globally optimal shortest path without unnecessary backtracking.

Manhattan vs. Euclidean Heuristics

Selecting the appropriate heuristic depends on the geometry and movement constraints of the search space.

Manhattan Distance (L₁ Norm)
h(n) = |x₁ - x₂| + |y₁ - y₂|

Calculates grid distance when diagonal movement is forbidden and agents can only travel in 4 cardinal directions (Up, Down, Left, Right).

✓ Perfectly consistent for orthogonal 4-directional grids.
Euclidean Distance (L₂ Norm)
h(n) = √((x₁ - x₂)² + (y₁ - y₂)²)

Calculates straight-line geometric distance ("as the crow flies"). Ideal for continuous coordinate planes, 8-directional grids, and GPS maps.

✓ Optimal for geographic road routing and unrestricted motion.

Why compare both heuristics?

On a standard 4-directional grid, Manhattan heuristic matches the actual step cost exactly, meaning it prunes dead ends more aggressively and usually explores fewer closed nodes. Euclidean distance underestimates 4-directional steps (\(\sqrt{2} \approx 1.414 < 2\)), so it explores slightly more frontier nodes while still maintaining admissibility and finding the identical optimal path.

Character Movement & Traversal

Once the optimal path array is computed by the A* solver, an autonomous agent (represented by 🤖 or 🏃) sequentially traverses the coordinates from Start to Goal.

1. Exploration Phase: Cells entered into the closed set trigger a subtle wave animation.
2. Path Reconstruction: Backtracking from the Goal via parent pointers reconstructs the path in \(O(L)\) steps.
3. Character Traversal: An animation loop updates the character's active cell coordinates at set intervals, with arrival celebration at Goal (G).

City Map Road Network Shortest Path

Geographic routing scales A* from 2D discrete grids to arbitrary weighted graph networks \(G = (V, E)\) with landmarks and road segments.

Vertices represent transit hubs, university campuses, airports, and hospitals. Edges represent bidirectional roads with real-world lengths (km) and speed classifications. The A* algorithm uses coordinate distance as \(h(n)\) to prune route alternatives and deliver instant turn-by-turn navigation.

REST API Reference

All algorithmic calculations, comparisons, road graphs, pricing, and system data are fully queryable via backend REST endpoints.

POST /api/astar/solve

Solves grid maze pathfinding. Payload: { grid, width, height, start:[r,c], goal:[r,c], heuristic }

POST /api/astar/compare

Runs both Manhattan and Euclidean heuristics side-by-side, returning comparative node counts and analytics.

GET /api/map/graph

Returns city road network nodes, coordinates, and road segments.

POST /api/map/route

Finds shortest driving path between two city locations. Payload: { startId, goalId }

GET /api/pricing/plans

Returns available pricing tiers (Free, Pro, Enterprise) stored in SQLite.
